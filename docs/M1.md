# M1：数据加载、归一化与可视化

本阶段只处理数据，不需要运行模型。图片在 CPU 上加载，后续训练阶段再将 batch 送到 MPS。

## 先运行，再按顺序阅读代码

在项目根目录运行：

```bash
uv run python -m scripts.inspect_data
uv run python -m scripts.inspect_data --split test --no-download
```

第一次运行会下载 MNIST 至 `data/MNIST/`，torchvision 会验证下载文件的校验和。之后可使用 `--no-download`，直接读取缓存。torchvision 的 MNIST 下载器会准备训练集和测试集文件，但每次 DataLoader 只读取所选 split。

命令会扫描所选 split 的所有 batch，检查数据形状、dtype、像素范围和标签范围，并在 `outputs/m1/` 保存：

- `mnist_train.png` / `mnist_test.png`：第一批中最多 64 张图片，每张图上方显示标签。
- `mnist_train.json` / `mnist_test.json`：样本数、批次数、第一批形状、最后一批大小、像素范围及各数字的计数。

阅读顺序：

1. `ddpm/data.py` 的 transform：观察像素值与形状如何变化。
2. `make_mnist_loader` 的 Dataset 与 DataLoader：理解单张图片如何组成一批。
3. `denormalize`：推导归一化的逆操作。
4. `scripts/inspect_data.py`：观察如何检查 batch 并绘图。

请使用 `python -m scripts.inspect_data`，使 Python 从项目根目录解析 `ddpm` 包；无需安装项目本身或修改 `sys.path`。

## 图片经过了什么变化？

| 步骤 | 单张图片形状 | 类型 | 范围 |
| --- | --- | --- | --- |
| MNIST 原图 | `28 × 28` | PIL 灰度图，像素为 uint8 | `[0, 255]` |
| `ToTensor()` | `[1, 28, 28]` | `torch.float32` | `[0, 1]` |
| `Normalize((0.5,), (0.5,))` | `[1, 28, 28]` | `torch.float32` | `[-1, 1]` |
| DataLoader 合批 | `[B, 1, 28, 28]` | `torch.float32` | `[-1, 1]` |

设原始像素为 p，则：

```text
u = p / 255
x = (u - 0.5) / 0.5 = 2u - 1
u = (x + 1) / 2          # 绘图前反归一化
```

黑色 `p=0` 对应 `x=-1`；白色 `p=255` 对应 `x=1`。这里的 0.5 和 0.5 用来映射范围，并不表示 MNIST 实际的均值和标准差。扩散模型并非只能使用此范围，这是本项目保持数据尺度一致的约定。

绘图时固定 `vmin=0, vmax=1`，避免 matplotlib 自动缩放掩盖像素尺度问题。`denormalize` 不会裁剪数值；它目前只用于已归一化的干净图片，不能直接把后续的带噪图片当成有效显示范围。

## Batch 和标签

`[B, C, H, W]` 分别是批大小、通道数、高度、宽度。MNIST 是灰度图，所以 `C=1`。标签是独立的 `[B]` int64 张量，取值为 0–9，与 batch 中每张图片一一对应。

训练 loader 默认打乱顺序；测试 loader 默认不打乱。检查命令为了便于复查，明确使用原始顺序。`seed` 控制打乱顺序；训练时不应每一步重建 loader，否则会反复从相同顺序开始。

`drop_last=False` 保留所有图片。`batch_size=64` 时，预期训练集为 60,000 张、938 批、最后一批 32 张；测试集为 10,000 张、157 批、最后一批 16 张。后续模型应读取实际 `images.shape[0]`，而不是假设每批永远有 64 张。

我们保留标签供 M6 条件生成使用；M2–M5 的无条件模型只读取图片，不使用标签。

## 自己动手检查

1. 将 batch size 改成 128，先推算最后一批有多少张，再运行验证。使用不同输出目录保留之前的结果：

   ```bash
   uv run python -m scripts.inspect_data --batch-size 128 --no-download --output-dir outputs/m1/batch128
   ```

2. 在 `make_mnist_loader` 设置 `shuffle=True`，打印前几个标签；比较相同 seed 与不同 seed 的结果。再次迭代同一个 loader 时，顺序可以改变，因为随机数生成器状态会前进。
3. 不看实现，写出从 `[-1, 1]` 返回 `[0, 1]` 的公式，并解释为什么不能对归一化图片直接转换成 uint8。

代码运行验收通过后，再确认自己能解释上面的公式、四个维度以及标签用途，随后进入 M2。
