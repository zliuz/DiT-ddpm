**状态：已完成并通过运行验收（2026-10-31）。6 处核心 TODO 由学习者实现，27 项 M4 测试与全量 64 项测试通过，CPU/MPS 训练及恢复已实测。**

M2 能构造带噪图片，M3 能预测噪声。M4 要把它们连接成一次次参数更新，并验证保存后可以继续训练。先在一个固定任务上检查网络能否拟合，再切换到每步重新采样的任务。

## 一步训练的目标和形状

$$
\begin{aligned}
\text{干净图片 }x_0\ [B,1,28,28]
&+ \text{时间步 }t\ [B]\text{、高斯噪声 }\epsilon\ [B,1,28,28]\\
&\longrightarrow \text{M2 }q_{\text{sample}}\\
\text{带噪图片 }x_t\ [B,1,28,28]
&+t\\
&\longrightarrow \text{M3 TinyDiT}\\
\text{预测噪声 }\epsilon_{\text{pred}}\ [B,1,28,28]
&\longrightarrow \text{与实际 }\epsilon\text{ 比较均值 MSE}\\
\text{标量 loss}&\longrightarrow \text{backward}
\longrightarrow \text{optimizer.step}.
\end{aligned}
$$

目标为

$$
\operatorname{mean}\left((\epsilon_{\mathrm{pred}}-\epsilon)^2\right),
$$

平均覆盖 batch、通道与像素。监督信号是调用 `q_sample` 时真正使用的噪声。因为噪声由我们采样，训练时不需要额外的人工标注。

`noise_prediction_loss` 返回仍连着计算图的 Tensor；`train_step` 完成反向传播和更新后，才将它转成 Python float 供日志使用。MSE 前检查完全相同的形状，避免 PyTorch 广播掩盖错误。

`model.train()` 与 `optimizer.zero_grad(set_to_none=True)` 每步调用。loss 非有限时停止；反向传播后检查所有可训练参数的梯度存在且有限，再允许更新参数。初版不加混合精度、梯度累积或学习率调度。

## 两种模式与随机状态

| 模式 | 图片选择 | 时间步与噪声 | 用途 |
| --- | --- | --- | --- |
| `overfit` | 子集最前面的 B 张 | 构造一次，此后复用同一 x_t/t/epsilon | 排查网络能否拟合一个固定任务 |
| `random` | 每次从固定子集有放回抽取 B 张 | 每次重新采样 | 检查扩散训练的随机任务与更新流程 |

固定目标包括图片、时间步和噪声三部分。只固定图片而不断重采样噪声，不属于这里的固定目标拟合。不要在训练循环里反复 `manual_seed`，用 `TrainingState.fixed_batch` 保存目标。

为了让初版恢复逻辑清楚，所有数据索引、时间步和噪声均用 **CPU 的 PyTorch RNG** 采样；日程也放在 CPU。`train_step` 才将三项张量搬到 CPU/MPS 的计算设备。M4 使用训练集前 `num_samples` 张图片，顺序固定，不维护跨 epoch 的 DataLoader 游标。

当前 TinyDiT 的前向计算没有随机算子（注意力 dropout=0），因此 checkpoint 中保存 CPU `torch.get_rng_state()` 足以延续本阶段的随机抽样。若后续加入 GPU 随机采样、dropout、Python random 或 NumPy 随机数，也要相应扩展保存与恢复逻辑。本阶段的精确连续性测试只在同一 CPU 环境比较，不承诺不同设备之间逐位一致。

## 配置与计数

`TrainConfig` 的每个字段均有代码注释。先使用默认 4 层、D=128、4 heads、P=4、float32、batch=8、AdamW lr=0.001、weight_decay=0 调试；它们是起点，训练效果和耗时尚待你完成代码后实测。

两个参数尤其容易混淆：

- `--num-steps 1000`：扩散日程长度 T，即时间步的取值范围。
- `--steps 100`：**本次额外进行 100 次优化器更新**。从 step=100 恢复后再传 100，结果应到 step=200。

`state.step` 是已经成功完成的更新总数，`len(state.losses)` 必须与它相等。每条 loss 在更新前计算，曲线横轴标记这条 loss 对应的第几次更新。

设备、输出路径和额外训练步数不属于严格比较的训练配置。mode、seed、子集大小、batch、日程、网络和优化器超参数都属于配置。恢复时重新指定原配置；不要悄悄接受不匹配的配置。命令行固定使用 MNIST 28×28 单通道数据，测试采用 8×8 合成图片加快验收。

## Checkpoint 格式约定

使用 `torch.save` 保存普通字典，顶层字段如下：

| 字段 | 内容 |
| --- | --- |
| `format_version` | 整数 1，便于之后识别格式变更 |
| `config` | `dataclasses.asdict(config)`，包含模型/日程/优化器与实验配置 |
| `model` | `model.state_dict()` |
| `optimizer` | `optimizer.state_dict()`，包含 AdamW 的动量、二阶矩和计数 |
| `step` | 累计完成的优化器更新数 |
| `losses` | 从第一步开始的 Python float 列表 |
| `fixed_batch` | None 或含 `x_t`、`t`、`target_noise` 的字典；张量为 CPU 副本 |
| `rng_state` | `torch.get_rng_state()` 返回的 CPU 字节张量 |

读取用 `torch.load(path, map_location="cpu", weights_only=True)`。先检查版本、配置和进度，再修改模型、优化器与 RNG。overfit 的非零进度必须带固定目标；random 的固定目标应为 None。用严格的 `model.load_state_dict` 检查参数匹配，优化器也必须加载，不能重新初始化后冒充恢复。

模型按配置创建并放到计算设备后，再恢复 checkpoint。CPU RNG 在恢复的最后设置，避免之前构造模型时消耗的随机数影响下一步采样。入口会重新读取相同 MNIST 训练子集，因此恢复时仍需使用相同的数据；数据本身不写入 checkpoint。

```bash
uv run pytest tests/test_training.py -q -k test_batch_

uv run pytest tests/test_training.py -q -k test_loop_

uv run pytest tests/test_training.py -q -k test_checkpoint_

uv run pytest tests/test_training.py -q

uv run ruff check .
uv run ruff format --check .
```

固定目标测试使用一个小型真实 TinyDiT，80 次 CPU 更新后，最后 10 次平均 loss 要低于初始值的 60%。这只是定位训练连线错误的短测试；它使用 8×8 合成数据，不代表默认 MNIST 配置也在相同步数内达到相同结果。

恢复测试在训练 3 步时保存，比较「继续训练 2 步」与「新建模型和优化器、恢复后训练 2 步」。CPU 上 loss 历史和最终参数应完全一致；只检查文件可以打开不足以验收恢复功能。

## 填写后再运行的小实验

先用 CPU 完成一个短运行：

```bash
uv run python -m scripts.train --mode overfit --device cpu --steps 20 \
  --output-dir outputs/m4/cpu_smoke
```

再在本机 MPS 做固定目标拟合，然后恢复同一个实验：

```bash
uv run python -m scripts.train --mode overfit --device mps --steps 100 \
  --output-dir outputs/m4/overfit

# 相同配置，追加 100 次更新；使用新目录保留原 checkpoint
uv run python -m scripts.train --mode overfit --device mps --steps 100 \
  --resume outputs/m4/overfit/checkpoint.pt --output-dir outputs/m4/overfit_resumed
```

检查固定任务的曲线是否明显下降；若下降不足，结合测试结果调整学习率、步数或网络规模并记录变化，不以单个 loss 值作结论。若更改配置，应另开实验，不能从严格校验的旧 checkpoint 直接恢复。

最后另开随机目标实验，再验证它的恢复：

```bash
uv run python -m scripts.train --mode random --device mps --steps 100 \
  --output-dir outputs/m4/random

uv run python -m scripts.train --mode random --device mps --steps 20 \
  --resume outputs/m4/random/checkpoint.pt --output-dir outputs/m4/random_resumed
```

每个成功运行的输出目录包含 `checkpoint.pt`、累计 `loss.png` 与 `report.json`。报告包括配置、实际设备、累计/本次更新步数、全部 loss 和本次训练耗时；checkpoint 和绘图时间不计入训练耗时。随机训练 loss 可以上下波动，先检查无 NaN/Inf、更新和恢复正确，不要求每一步都下降。

入口只读取 M1 已下载的 MNIST，不自动联网下载。`--help` 可以查看参数；未填写 TODO 时入口退出并指出未完成的步骤。`outputs/` 已被 Git 忽略，checkpoint、报告和曲线无需提交。
